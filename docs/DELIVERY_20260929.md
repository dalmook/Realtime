Windows의 Oracle 테스트는 드라이버와 OCI 파일 존재 조건을 모의 처리한 단위 테스트입니다. 실제 Oracle 접속/Instant Client 로딩 성공을 의미하지 않습니다.

실제 DEMO 실행 검사에서는 독립 임시 SQLite, 다섯 화면을 포함한 HTML의 HTTP 200 응답, EA/BOX/USD/EQ_DRAM/EQ_FLASH 각각의 KPI와 시간대 합계, 필터·아이템·거래선·이벤트·목표·집중관리 API를 확인했습니다.

별도 로컬 Chromium 화면 검사 33개도 통과했습니다. 다섯 화면, 수기 목표 CRUD, 집중관리, 다섯 지표, 필터·합계, CSV BOM, 다크/모바일, JavaScript 오류 및 정적 데모 외부 통신을 검사했습니다. 해당 브라우저 검사는 단일 HTML을 메모리에 로드한 방식이며, 실제 HTTP 서버 실행 검사와는 별도로 수행했습니다.

## 실행

합성 데이터로 확인: ZIP 압축 해제 후 `DEMO.cmd`. Python 3.11 이상만 필요하며 회사 서비스나 운영 DB를 사용하지 않습니다.

Python 없이 화면만 확인: `SCM_Demo.html`을 브라우저에서 엽니다.

회사 실행: 새 폴더에 ZIP 해제 → `SETUP.cmd` → `.env` 연결 정보 입력 → `CHECK.cmd` → `START.cmd`.

기본 로컬 주소: `http://127.0.0.1:8765/`. Oracle Thick 드라이버와 Instant Client는 회사 승인 설치본이 필요합니다. 코드/DB 경로를 분리했으며, 업데이트 시 기존 DB를 지우지 않습니다. 업데이트 전 `BACKUP.cmd`를 사용하고 `.env`와 회사에서 수정한 로컬 매핑을 보존하세요.

## GitHub Pages 상태 및 남은 계정 설정

Release 발행과 네 환경의 실행 테스트는 모두 성공했습니다. 동일 실행의 `pages` 작업만 실패했습니다.

실제 오류: `Create Pages site failed: Resource not accessible by integration`.

현재 연동에서 새 Pages 사이트를 최초 활성화할 수 없어 공개 웹 주소는 아직 열리지 않습니다. 파일 다운로드 데모와 로컬 실행에는 영향이 없습니다.

저장소 소유자가 https://github.com/dalmook/Realtime/settings/pages 에서 **Build and deployment → Source → GitHub Actions**를 선택한 뒤, 위 Actions 실행의 **Re-run failed jobs**를 실행하면 준비된 합성 화면 배포 작업만 다시 시도할 수 있습니다. 토큰이나 비밀번호를 채팅 또는 저장소에 넣지 마세요.

## 복원 및 운영 범위

끊긴 업로드에서 91개 완전한 파일을 추출해 MANIFEST로 검증하고, 검증된 기존 패키지의 수집 엔진·SQL·테스트·도구 24개를 보완했습니다. 임시 업로드 조각과 복구 전용 워크플로는 main에서 제거했습니다. 마스킹된 원본 코드 보존본은 `docs/restoration`에 있습니다. 실행을 막던 경로·API·집계 오류를 수정한 버전이므로 원본 81개 파일의 바이트 단위 동일 복제본은 아닙니다.

회사 Splunk/Oracle 실제 접속, SAP 숫자 대조, 사용자 PC의 드라이버 조합은 검증 범위 밖입니다. 실운영 BOX는 CARTON 의미를 확인한 뒤 활성화해야 하며, 실운영 재고 원천은 별도 연결이 필요합니다. 재고 목표나 임의 추정 수량은 만들지 않습니다. GitHub에는 실제 비밀번호나 업무 DB를 올리지 않습니다.
